# ADR-0039: A native deadline has two parts, and only one is a handler budget

## Status

Accepted, 2026-11-13.

## Context

A command-hook harness gives the generated dispatcher one deadline per native
event. Inside that window the dispatcher runs every matching hook in turn, each
under its own budget (`HookSpec.timeoutMs`, or `runtime.timeoutMs` when the hook
declares none). The deadline therefore covers more than handlers: the harness
spends the same window starting the process — on Windows a `cmd.exe` and then a
`node.exe` — writing stdin, and reading stdout.

`nativeTimeoutSeconds` already said so: a fixed `+ 1` second for "process start,
stdin read, decode and stdout flush". But it was a constant with no policy name
and no way to raise it, and it was the same second for every budget.

The cost showed up as a CI flake. A Codex 0.156.1 Code Mode deny drive, built
with a 1 s handler budget and so a 2 s native deadline, printed
`hook: PreToolUse Failed` and ran the command the guard denied.
`.capture/codex-hook-failure` measured why: on a contended Windows host Codex's
own clock spent 1.5–2.0 s per hook on start-up while the handler ran in under
200 ms, and the same drive failed open in 2 of 15 runs at 2 s and 0 of 15 at
11 s. A timed-out `PreToolUse` is non-blocking on Codex, so the guard's deny is
lost, not postponed (ADR-0008 record for 0.156.1).

Raising the constant would have fixed that instance and left a consumer on a
slower host no way to say so. A per-hook field would have let a guard's own
declaration shrink the margin that protects it.

## Decision

1. **`runtime.processAllowanceMs` is the start-up allowance**, default `5_000`.
   It is build-time only: the bundled dispatcher never reads it. It sizes each
   native deadline.
2. **A deadline is the event's handler budgets plus one allowance**:
   `ceil((sum of budgets + processAllowanceMs) / 1000)` seconds. The allowance is
   added once per native event, not once per hook, because one dispatcher
   process serves every hook on it.
3. **A harness cap shrinks the allowance, never the handler budgets.** For an
   event with a ceiling, the allowance is
   `min(processAllowanceMs, max(0, ceiling * 1000 - sum of budgets))` — never
   more than the policy grants, and less when the cap leaves less room. Taking
   all the headroom instead would turn the deadline into the cap itself. The
   dispatcher's own budgets still fit, so nothing is hidden; only budgets that
   alone exceed the cap reach `assertNativeTimeoutFits`, whose refusal is
   unchanged.
4. **The default is evidence-sized, and the evidence's limit is stated.** 5 s
   covers the 1.5–2.0 s start measured under ordinary contention. Adding the 5 s
   handler budget, a 10 s deadline exceeds the worst Codex-clock wall a 2 s drive
   produced (6.7 s). The capture's ~9 s start, under 96 busy-loop processes on 32
   cores, is not covered by default; `processAllowanceMs` is the escape hatch for
   a host that needs it.
5. **The field stays out of the policy the shim receives.**
   `dispatcherRuntimePolicy` passes only the values the dispatcher reads.
   `DEFAULT_RUNTIME` carries the field with the other defaults, so the bundled
   default object has it too, and nothing in the dispatcher reads it there: it
   sizes deadlines and stops.
6. **Generated artifacts change for every target.** At defaults every native
   timeout grows by the 4 s the allowance gained (1 s → 5 s), so committed
   example artifacts are rebuilt in the same change (ADR-0006), and the release
   that ships it names the change in its highlights.

## Consequences

- At defaults a `PreToolUse` deadline becomes 10 s on Codex, Claude and Copilot
  (5 s handler + 5 s allowance). Codex's `SessionEnd` keeps 3 s: Codex clamps
  that event, and the allowance takes the 1 s that is left. A plugin with a
  `session.end` hook and the default 5 s handler budget still cannot build for
  Codex, because the handler budget alone exceeds the cap. That is pre-existing,
  unchanged, and the refusal names the fix. Claude's `SessionEnd` cap is 60 s,
  so the 10 s default sits well inside it; only when the handler budgets exceed
  55 s (60 s minus the allowance) does that cap shrink the allowance.
- The dispatcher's handler timer is unchanged, so a hung handler still ends at
  its budget; the added time covers a slow start, or a process that died before
  it answered. The visible cost is a longer wait before the harness gives up on
  a wedged process.
- A consumer on a slower host raises `processAllowanceMs` and nothing else
  changes. Budgets that already fit stay as they are.
- A project integration generated by an earlier version reports its hook files
  as modified until `sync` runs again, because the native timeouts changed.
- The playback lane goes back to the product policy, so the CI gate exercises
  the artifact a consumer gets instead of a lane-only budget. The capture
  reproduces its tighter configuration by overriding both the handler budget and
  the allowance.
- No harness shape is claimed here. `.capture/codex-hook-failure` measured
  Codex's deadline behaviour; the allowance is a build-time number that only
  adds headroom to it.

## Alternatives considered

- **Raise the `+ 1` constant.** One line, no surface. It fixes the instance,
  leaves no escape hatch, and keeps a policy number inside a derivation nobody
  can find.
- **A per-hook `processAllowanceMs`.** Start-up is per process, so a hook-level
  value would be ignored for every hook but one, or multiply the deadline; and
  it would let a guard declare a smaller margin than the one protecting it.
- **Clamp the deadline to the cap.** The reasoning in `assertNativeTimeoutFits`
  still holds: lowering only the manifest leaves the bundle's budgets unchanged
  and hides the mismatch. Only the allowance, which is not a handler budget, may
  shrink.
- **Leave it to playback tuning (the first shape of this change).** The lane
  would carry a second copy of the same policy, divergent from the product, and
  the fail-open would remain for consumers. The capture supplies the number, so
  the number belongs in the model.
