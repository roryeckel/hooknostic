## 1. Claude Code (R2, validated against 2.1.238)

### Process model

Command hooks: JSON event on **stdin** → subprocess → JSON on **stdout** + exit code.
Hook types beyond `command` exist (`http`, `mcp_tool`, `prompt`, `agent`); the adapter
emits `command` hooks only.

### Native events relevant to the normalized vocabulary

| Normalized event | Native event | Notes |
| --- | --- | --- |
| `session.start` | `SessionStart` | matcher = `startup\|resume\|clear\|compact\|fork`; payload `how`, optional `model` |
| `session.end` | `SessionEnd` | matcher = end reason |
| `prompt.before` | `UserPromptSubmit` | payload `user_prompt`; no matcher support |
| `tool.before` | `PreToolUse` | payload `tool_name`, `tool_input`, `tool_use_id` |
| `tool.after` | `PostToolUse` | tool already ran; exit-2 not honored |
| `tool.error` | `PostToolUseFailure` | tool already failed |
| `permission.request` | `PermissionRequest` | exit-2 **not** honored; use `permissionDecision` |
| `context.compact.before` | `PreCompact` | matcher `manual\|auto`; blockable |
| `context.compact.after` | `PostCompact` | |
| `agent.start` | `SubagentStart` | matcher = agent type; observe-only (stderr to user) |
| `agent.stop` | `SubagentStop` | blockable (prevents subagent stop) |
| `turn.stop` | `Stop` | blockable (prevents stopping) |

Many further native events exist (`Setup`, `Notification`, `PostToolBatch`,
`TaskCreated/Completed`, `WorktreeCreate/Remove`, `ConfigChange`, `FileChanged`,
`Elicitation*`, `MessageDisplay`, `TeammateIdle`, `InstructionsLoaded`,
`UserPromptExpansion`, `StopFailure`, `PermissionDenied`, …). Per the design rule these
stay vendor/extension surface; do **not** promote them to normalized events without a
second harness demonstrating shared semantics.

### Common stdin fields

`session_id`, `prompt_id`, `transcript_path`, `cwd`, `permission_mode`,
`hook_event_name`, and on subagent events `agent_id` / `agent_type`. Tool events add
`tool_name`, `tool_input`, `tool_use_id`.

### Output semantics (fields verified per event)

- Universal: `continue: false` + `stopReason`, `systemMessage`, `suppressOutput`.
- Tool events use `hookSpecificOutput`: `{ hookEventName, permissionDecision:
  "allow"|"deny"|"escalate", permissionDecisionReason, additionalContext, updatedInput }`.
  - `updatedInput` (input rewrite): **PreToolUse only**.
  - `additionalContext` (model-visible): `UserPromptSubmit`, `UserPromptExpansion`,
    `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `PostToolBatch`,
    `PermissionRequest`.
- Prompt/stop-family events use top-level `decision: "allow"|"deny"` (deny on
  `Stop`/`SubagentStop` = keep going) + `reason`.
  > **Corrected 2026-08-29 (2.1.250):** the enum is `"approve"|"block"`, not
  > `"allow"|"deny"`. A `"deny"` response is rejected and does not prevent a stop;
  > `"block"` prevents it, matching Codex. See `.capture/claude-output`. Left in
  > place rather than rewritten — this file is a dated snapshot, and the adapter
  > profile is the normative source for any cell (§14).
- Exit code 2 = blocking error **only** on events that honor it: `PreToolUse`,
  `UserPromptSubmit`, `Stop`, `SubagentStop`, `PreCompact`, and others per the reference
  table. **Not honored** on `PermissionRequest`, `PostToolUse`, `PostToolUseFailure`,
  `SessionStart`, `SessionEnd`, `SubagentStart`. JSON `permissionDecision: "allow"`
  cannot override exit 2. Other nonzero exits are non-blocking errors.
- `SessionStart` / `UserPromptSubmit` plain-text stdout (exit 0) is added as context;
  the adapter uses explicit JSON instead.
  > **Scope note, 2026-08-29 (2.1.250):** this does not generalize to the stop
  > family. Plain exit-0 stdout on `Stop` is discarded — not shown, not context,
  > not blocking. The user-visible channel there is top-level `systemMessage`,
  > which renders as a system notice and is never seen by the model.

### Configuration / plugin artifacts

- Plugin hook config: `<plugin-root>/hooks/hooks.json`
  (`{ description?, hooks: { EventName: [{ matcher?, hooks: [{ type: "command",
  command, args?, timeout?, async?, statusMessage? }] }] } }`).
- **Exec form** (with `args` array) bypasses the shell — use it for generated hooks.
- Placeholders / env: `${CLAUDE_PLUGIN_ROOT}`, `${CLAUDE_PLUGIN_DATA}`,
  `${CLAUDE_PROJECT_DIR}`; same values exported as env vars to the subprocess.
- Matchers: `""`/`"*"`/omitted = match all; plain word-lists (`Bash|PowerShell`) exact;
  anything else is unanchored JS regex. Tool-event matchers match tool names; MCP tools
  appear as `mcp__<server>__<tool>` (plugin-bundled: `mcp__plugin_<plugin>_<server>__<tool>`).
- Standalone plugin needs `.claude-plugin/plugin.json`.
- Hook timeout field is **seconds** (default 600 for command hooks).

## 2. OpenAI Codex CLI (R3, validated against 0.148.0)

### Process model

Same command-hook shape as Claude: JSON stdin → subprocess → JSON stdout/exit code.

### Events (turn-scoped + session)

`PreToolUse`, `PermissionRequest`, `PostToolUse`, `PreCompact`, `PostCompact`,
`UserPromptSubmit`, `SubagentStart`, `SubagentStop`, `Stop`, `SessionStart`,
`SessionEnd`.

Notable absences vs Claude: **no `PostToolUseFailure`** (normalized `tool.error` is
unsupported), no `Setup`/`Notification`/task/worktree family.

### Common stdin fields

`session_id`, `transcript_path` (nullable), `cwd`, `hook_event_name`, `model`,
`permission_mode`; turn-scoped events add `turn_id`. Tool events: `tool_name`,
`tool_use_id`, `tool_input` (+ `tool_response` on PostToolUse). Stop events:
`stop_hook_active`, `last_assistant_message`.

### Output semantics

- Common: `continue`, `stopReason`, `systemMessage`, `suppressOutput`.
- `PreToolUse`: block via `permissionDecision: "deny"` + `permissionDecisionReason`
  (or exit 2 + stderr); rewrite via `permissionDecision: "allow"` + `updatedInput`.
- `PermissionRequest`: `decision: { behavior: "allow" }` or
  `{ behavior: "deny", message }`.
- `PostToolUse` / `UserPromptSubmit` / `Stop` / `SubagentStop`:
  `decision: "block"` + `reason` (or exit 2). On stop events "block" = prevent stop.
- `additionalContext` via `hookSpecificOutput: { hookEventName, additionalContext }`.

### Configuration / plugin artifacts — **verified against 0.148.0, differs from docs**

- `codex features` on 0.148.0: `hooks` is **stable/enabled**, but
  `plugin_hooks` is **removed** — plugin-bundled `hooks/hooks.json` does NOT
  load, contrary to R3. The adapter therefore emits **repo-level** artifacts
  (`mode: "local"`): `.codex/hooks.json` + bundled runtime.
- Verified discovery: `<git-repo-root>/.codex/hooks.json`, loaded **only for
  trusted projects** (`[projects.'<path>'] trust_level = "trusted"` in
  `~/.codex/config.toml`). Each hook additionally needs persisted hook trust
  (`[hooks.state.'<path>:<event>:i:j'] trusted_hash = "sha256:…"`) or
  `--dangerously-bypass-hook-trust`.
- Verified hooks.json shape: **PascalCase** event keys, Claude-compatible
  `{hooks: {Event: [{matcher?, hooks: [{type: "command", command, timeout}]}]}}`.
  (Binary strings also mention `commandWindows`, `statusMessage`,
  `additionalContextLimit`, `async` handler fields and kebab-case event names
  on an internal config path.)
- Hook payload/response contracts are embedded in the binary as draft-07 JSON
  Schemas (`<event>.command.input` / `.output`, `additionalProperties: false`);
  fixtures cross-validated against them. Key wire facts:
  `permissionDecision ∈ allow|deny|ask`; PreToolUse rewrite = `allow` +
  `updatedInput`; PostToolUse `decision: "block"` + `updatedMCPToolOutput`
  (MCP only); PermissionRequest `hookSpecificOutput.decision.behavior ∈
  allow|deny` (+`message`; `updatedInput`/`updatedPermissions`/`interrupt`
  reserved, fail closed); PreCompact/PostCompact outputs have **no decision**
  (compaction not blockable).

### Tool coverage caveats (document; not a security boundary)

Covered: shell (`Bash` match), unified exec (`exec_command` → `Bash`), `apply_patch`
(matches `apply_patch`/`Edit`/`Write`), MCP tools (`mcp__server__tool`), local function
tools (`update_plan`, `spawn_agent` → `Agent`). **Not covered:** hosted tools
(e.g. `WebSearch`); `write_stdin` does not re-trigger `PreToolUse` on existing sessions.

### Version caveat

The docs do not pin a CLI version; the design doc assumed a hypothetical `>=1.34`.
Actual installed CLI is **0.148.0**. The adapter capability profile must be validated by
fixture capture against 0.148.0, recording `unsupported`/`approximate` honestly where
0.148.0 lacks a documented behavior.

## 3. OpenCode (R4, validated against 1.18.18)

### Process model

Plugins are persistent JS/TS modules:
`export const MyPlugin = async ({ project, client, $, directory, worktree }) => ({ ...hooks })`.
Loaded from `.opencode/plugins/` (project) and `~/.config/opencode/plugins/` (global), or
npm packages listed in `opencode.json` `"plugin"` array. Types:
`@opencode-ai/plugin`.

### Hook callbacks relevant to normalized vocabulary

| Normalized event | Native callback | Notes |
| --- | --- | --- |
| `tool.before` | `tool.execute.before(input, output)` | `input.tool` name; mutate `output.args` to rewrite; **throw to block** |
| `tool.after` | `tool.execute.after(input, output)` | mutate output to replace |
| `permission.request` | `permission.asked` (+ `permission.replied`) | verify exact reply mechanism during fixture capture |
| `session.start` | `session.created` | |
| `session.end` | `session.deleted` (approximate) | |
| `turn.stop` | `session.idle` (approximate) | observation only |
| `context.compact.before` | `experimental.session.compacting` | `output.context` array to inject context; `output.prompt` replaces compaction prompt; experimental-prefixed |
| `tool.error` | — | no distinct failure callback (unsupported) |
| `prompt.before` | — | no pre-prompt callback on stable surface (verify at capture) |
| `agent.start` / `agent.stop` | — | no subagent lifecycle callbacks (verify at capture) |

Other native callbacks (vendor extension surface): `session.updated/error/status/diff/
compacted`, `message.*`, `file.edited`, `file.watcher.updated`, `command.executed`,
`lsp.*`, `shell.env`, `tui.*`.

### Effect mechanics

- Block tool: `throw new Error("reason")` inside `tool.execute.before`.
- Rewrite input: mutate `output.args` in `tool.execute.before`.
- Replace output: mutate output object in `tool.execute.after`.
- Add context: only at compaction (`output.context`); no general model-visible context
  injection on tool events → `*.context.add` is unsupported/approximate on OpenCode.

### Load order

Global config → project config → global plugins → project plugins.

## 4. Agent Plugins 1.0 (R1)

- `plugin.json`: closed schema — `$schema` (required,
  `https://agent-plugins.org/schemas/1.0.0/plugin.schema.json`), `name` (required,
  1–64 chars, lowercase alnum/hyphen/period), optional `version`, `description`,
  `author{name,email,url}`, `homepage`, `repository`, `license`, `keywords`,
  `extensions`. Unknown root fields: report + ignore (non-fatal); other violations
  fatal.
- Client extensions: reverse-domain namespaces, either under the `extensions` manifest
  key or as **top-level namespaced directories** — e.g.
  `com.example.client/hooks/hooks.json` (the spec's own example shape).
- Portable components: `skills/<name>/SKILL.md`, `mcp.json`
  (`$schema` version must match plugin.json's).
- `${PLUGIN_ROOT}` / `${PLUGIN_DATA}` expand only in mcp.json `args`/`env`
  values/`cwd`.
- Namespace choices for generated output (confirm against client docs at emission time):
  `com.anthropic.claude-code/`, `com.openai.codex/`; OpenCode extension namespace has no
  published reverse-DNS convention yet — the adapter emits `.opencode/plugins/` local
  mode in v0.1.

## 5. Sondera pattern (R5)

Adapter-interface precedent: per-agent adapters normalize harness-specific tool
invocations into shared categories (`ShellCommand`, `FileRead`, `FileWrite`, `FileEdit`,
`WebFetch`, `ToolCall`) before shared logic runs — Claude's `Bash`, Cursor's shell hook,
Copilot's and Gemini's `bash` all collapse to `ShellCommand`. Hooknostic adopts the
normalization pattern (as `ToolInvocation.kind`) and deliberately excludes Sondera's
policy-engine/reference-monitor concerns.

## 6. Initial capability-mapping observations (to be encoded as adapter matrices)

| Capability | Claude 2.1.x | Codex 0.148.x | OpenCode 1.18.x |
| --- | --- | --- | --- |
| `tool.before.block` | exact (`permissionDecision: deny` / exit 2) | exact (`deny` / exit 2) | exact (throw) |
| `tool.before.requestApproval` | exact (`permissionDecision: escalate`) | exact (`permissionDecision: ask`) | unsupported (no ask-from-hook) |
| `tool.before.input.replace` | exact (`updatedInput`) | exact (`allow` + `updatedInput`) | exact (mutate `output.args`) |
| `tool.before.context.add` | exact (`additionalContext`) | exact (`hookSpecificOutput.additionalContext`) | unsupported |
| `tool.after.output.replace` | unsupported (no documented replace) | approximate (`updatedMCPToolOutput`, MCP tools only) | exact/emulated (mutate output) |
| `tool.after.blockContinuation` | approximate (stderr shown to model; exit 2 not honored) | exact (`decision: "block"`) | unsupported |
| `tool.error.observe` | exact (`PostToolUseFailure`) | unsupported | unsupported |
| `permission.request.observe` | exact | exact | exact (`permission.asked`) |
| `session.start.context.add` | exact (stdout/JSON context) | exact (`hookSpecificOutput.additionalContext`) | unsupported |
| `context.compact.before.block` | exact (blockable `PreCompact`) | unsupported (no decision in pre-compact output wire) | unsupported (can inject/replace, not block) |
| `turn.stop.prevent` | exact (`Stop` deny/exit 2) | exact (`decision: "block"`) | unsupported (`session.idle` observe-only) |

"verify at capture" cells must be resolved by real fixture capture before the adapter
matrix claims a support level.
